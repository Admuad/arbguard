# ArbGuardChecker — Stylus (Rust) invariant checker

Pure invariant math for ArbGuard, compiled to WebAssembly and deployed as
a Stylus program on Arbitrum. The Solidity `ArbGuard.sol` calls these three
functions via cross-contract call before a guarded protocol executes a
sensitive action (withdraw / mint / swap / borrow). Every function is pure:
no storage reads, no storage writes, no cross-contract state.

This crate is a **gas-optimisation swap** for the invariant math inside
`ArbGuard.sol`, not load-bearing: the Solidity fallback (`_checkInvariants`
in `ArbGuard.sol`) implements the same rules, so the system works
end-to-end with or without this checker.

## The three checks

All amounts are `uint256`; bps = basis points (10000 = 100%). All
arithmetic is **overflow-safe and fail-closed**: any overflow returns
`false` (block the action) instead of wrapping. A check that cannot be
proven safe must block — never fail-open.

| Function | Rule | Edge cases |
|---|---|---|
| `check_outflow(amount_out, window_outflow, max_outflow)` | `window_outflow + amount_out <= max_outflow` | `window + amount` overflow → `false`. Exact-boundary passes. |
| `check_price_deviation(price, twap, max_bps)` | `twap > 0` and `\|price - twap\| * 10000 <= twap * max_bps` | `twap == 0` → `false` (no reference price). Either multiplication overflow → `false`. |
| `check_share(amount_out, tvl, max_bps)` | `tvl == 0` → pass, else `amount_out * 10000 <= tvl * max_bps` | `tvl == 0` means "no TVL context supplied", so pass. Either multiplication overflow → `false`. |

The same logic exists twice in `src/lib.rs` by design: plain Rust free
functions (`pub fn check_outflow(...) -> bool`, ...) that `cargo test`
exercises directly, and `#[public]` entrypoint methods on the
storage-less `ArbGuardChecker` struct that delegate to them — so the
on-chain behaviour and the unit tests run the same code.

## ABI — what `ArbGuard.sol` must call (Week 2 wiring)

Generated by `cargo stylus export-abi` (2026-11-09). The checker is
stateless and every function is `view` — call it with `staticcall` from
`ArbGuard.sol`; no state change, no gas-heavy storage access.

```solidity
// SPDX-License-Identifier: MIT-OR-APACHE-2.0
pragma solidity ^0.8.23;

interface IArbGuardChecker {
    function checkOutflow(uint256 amount_out, uint256 window_outflow, uint256 max_outflow) external view returns (bool);
    function checkPriceDeviation(uint256 price, uint256 twap, uint256 max_bps) external view returns (bool);
    function checkShare(uint256 amount_out, uint256 tvl, uint256 max_bps) external view returns (bool);
}
```

Function selectors (verified with `cast sig`, Foundry 1.9.0):

| Function | Selector |
|---|---|
| `checkOutflow(uint256,uint256,uint256)` | `0x932511af` |
| `checkPriceDeviation(uint256,uint256,uint256)` | `0x2e2742ce` |
| `checkShare(uint256,uint256,uint256)` | `0x22b033b8` |

Suggested `ArbGuard.sol` integration (Week 2, not this run):

```solidity
IArbGuardChecker public checker; // set once by the owner (zero address = Solidity fallback)

function _checkInvariants(Action memory action, Policy memory policy) internal view {
    if (address(checker) == address(0)) {
        // Solidity fallback path (existing _checkInvariants math).
        _checkInvariantsSolidity(action, policy);
        return;
    }
    if (!checker.checkOutflow(action.amountOut, windowOutflow(action.token), policy.maxOutflowPerBlock))
        revert ArbGuardViolation("OUTFLOW_PER_BLOCK");
    if (!checker.checkPriceDeviation(action.price, action.twapPrice, policy.maxPriceDeviationBps))
        revert ArbGuardViolation("PRICE_DEVIATION");
    if (!checker.checkShare(action.amountOut, tvl(action.token), policy.maxSingleShareBps))
        revert ArbGuardViolation("SHARE_OF_TVL");
}
```

Notes for the wiring slice:

- The checker takes **raw numbers only** — it does not know about
  policies, windows, or tokens. `ArbGuard.sol` owns all state: it must
  track `windowOutflow` per token per block and pass the current TVL.
- `checkShare` with `tvl == 0` **passes by design**. If a guarded
  protocol has not supplied TVL (e.g. no deposits yet), the share rule is
  a no-op rather than a blocker. If that is ever the wrong default for a
  given integration, enforce `tvl > 0` in `ArbGuard.sol` before calling.
- `checkPriceDeviation` with `twap == 0` **fails by design**. Callers
  must have a TWAP available; if a pool has no TWAP yet, skip the call
  (or fail closed) in `ArbGuard.sol` — do not pass 0 and expect a pass.
- The checker has **no storage and no owner** — nothing to initialise,
  no admin functions, nothing to upgrade. Deploy once, point
  `ArbGuard.checker` at it.

## ⛔ BLOCKER: new Stylus activations are PAUSED on Arbitrum (2026-11-09)

`cargo stylus check` **does not pass** — not because of this code (the
WASM compiles cleanly at 5.7 KB compressed, and `cargo test` is green),
but because the Arbitrum Security Council paused **all new Stylus
contract activations** on 2 Oct 2026 (emergency action, AI-assisted
hand-crafted-WASM attack risk). The pause is implemented by setting the
activation gas to `2^64 - 1`, which `cargo-stylus` reports as:

```
error: Stylus activations appear to be paused on this chain
       (activation gas charge is 18446744073709551615)
```

Verified 2026-11-09 ~23:21–23:36 WAT against **both** public RPCs:

- Arbitrum Sepolia (`https://sepolia-rollup.arbitrum.io/rpc`) — same error.
- Arbitrum One (`https://arb1.arbitrum.io/rpc`) — same error.

The official notice (docs.arbitrum.io/notices/stylus-activation-pause-notice)
names One and Nova; Sepolia returns the identical sentinel empirically, so
treat Sepolia as paused too. Already-activated Stylus contracts keep
running; **no new Stylus contract can be activated anywhere right now**,
and no end date has been announced. A resumption proposal (Stylus
Activation Contract: audit + Foundation signature before activation) went
through a temperature-check vote ending 5 Nov 2026; as of this writing
there is no live resumption.

**Consequence for the plan:** the Stylus hard gate (Mon 23 Nov — checker
deployed + passing on Sepolia) **cannot be met while the pause is in
effect**, through no fault of this code. The Solidity fallback in
`ArbGuard.sol` is therefore the shipping path unless activations resume
before the gate. This crate stays ready: tested, ABI-exported, and
deployable the moment the pause lifts. Re-check with

## Environment gotchas hit during setup (so nobody re-pays them)

1. **rustup install interrupted, then half-installed toolchain.** The
   first `rustup` run was cut mid-download and left a broken
   `stable-x86_64-unknown-linux-gnu` ("missing manifest"). Fix:
   `rustup toolchain uninstall stable && rustup toolchain install stable`.
2. **cargo's HTTP client stalls through this VM's egress proxy, while
   curl works fine.** `cargo install cargo-stylus` repeatedly failed with
   `transfer too slow: failed to transfer more than 10 bytes in 30s`
   on `.crate` downloads (curl fetched the same files at ~300–500 KB/s).
   Workaround used: extracted the `cargo-stylus-0.10.10` crate's
   `Cargo.lock`, downloaded all 637 dependency `.crate` files with
   parallel `curl` into `~/.cargo/registry/cache/`, then
   `cargo install ... --offline`. If a future `cargo build` needs a crate
   version not in the cache, expect the same stall — pre-fetch it with
   curl from `https://static.crates.io/crates/<name>/<name>-<version>.crate`
   rather than retrying cargo's downloader.
3. **`/tmp` is a 512 MB tmpfs and fills up.** The first `cargo install`
   build dir (`/tmp/cargo-install*`, ~508 MB) filled it and `cc` died
   with `No space left on device` while compiling `aws-lc-sys`'s `bcm.c`.
   Rule for this VM: **never build in `/tmp`**. Use
   `TMPDIR=$HOME/.cargo-build-tmp` and
   `CARGO_TARGET_DIR=$HOME/.cargo-install-target` for installs, and keep
   project checkouts under `$HOME` (the hello-world proof lived in
   `~/.hello-stylus`, not `/tmp`).
4. **Template bug: `cargo stylus new` ships a test it cannot compile.**
   The generated `src/lib.rs` uses `stylus_sdk::testing::*`, but the
   generated `Cargo.toml` has no dev-dependency enabling it. Fix (already
   applied here, per the official quickstart):
   ```toml
   [dev-dependencies]
   stylus-sdk = { version = "0.10.10", features = ["stylus-test"] }
   ```
5. **`rclite` version conflict after adding the test feature.**
   `stylus-sdk` 0.10.10 wants `rclite =0.4.1` for the test feature but
   the template lockfile pinned `0.4.2`; cargo refuses to reconcile them
   in place. Fix: delete `Cargo.lock` and let cargo re-resolve
   (it picks `rclite 0.4.1`, satisfying both requirements).
6. **`cargo stylus check` needs an explicit endpoint here.** No Docker
   and no local nitro test node on this VM, so the default
   `http://localhost:8547` is unreachable. Use the public Sepolia RPC
   (read-only activation dry-run, no key, no deploy).
7. **Memory pressure:** the VM runs ~1 GB free while other slices build.
   `cargo install` was run with `-j 2` to keep `rustc`/`cc` from
   competing for RAM. The full `cargo-stylus` build took ~13 min.
